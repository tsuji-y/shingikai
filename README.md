## www.mod.go.jp のアクセス制約

2026-11-19 にクラウド環境（米国のデータセンター経由）から実測した結果。国内回線の PC からも、HTML は 403、PDF と RSS は 200 だった。

| 対象 | スクリプトからの結果 |
|---|---|
| HTML・ディレクトリ URL・`sitemap.xml` | 403。Cloudflare のボット検証（`cf-mitigated: challenge`） |
| PDF | 200 |
| `/j/rss/update.xml`、`/j/rss/news.xml` | 200。ただし Python 既定の User-Agent では 403 |
| `robots.txt` | 200。`Disallow` は `/a/` と `/sp/j/` のみ |

ボット検証は運営側が自動アクセスを弾くための仕組みなので、ステルス化などで突破しない。検証が出ない経路で取得する。PDF の URL を推測して総当たりすることもしない。

HTML は通常のブラウザ（国内回線の Chrome）で開けば検証は表示されない。そこで HTML はブラウザの中で取得している（次節）。サイトのコンテンツは「公共データ利用規約（第1.0版）」に準拠して利用できる（[コンテンツの利用について](https://www.mod.go.jp/j/info/contents.html)）。

### WARP

防衛省のページは、古い回の資料や一覧を国立国会図書館のアーカイブ（WARP、`warp.da.ndl.go.jp`）へのリンクにしている。リンク先の `/info:ndljp/pid/…` は閲覧用の枠だけを返すページで、保存されている本体（PDF も HTML も）は枠の中に読み込まれる `/2025…/www.mod.go.jp/…` のような別の URL にある。WARP の `robots.txt` はこの `/20` で始まるパスを全ロボットに対して禁じている（ほかに `/search`、`/web/`、`/collections/`）。したがって WARP 上の本体はスクリプトで取得しない。WARP にしかない資料（PDF 1,297 件、一覧などの HTML 315 件）の中身は、このデータベースには入っていない。

## ページの取得

1. ブラウザで www.mod.go.jp のページを開き、`mod/fetch_in_browser.js` を実行する。サイト内のパスを 1 件ずつ、2 秒強の間隔で取得し、403・429 が返ったら止まる。
2. 保存されたページ束を展開する。

```bash
python3 mod/ingest_pages.py mod_pages.json
```

3. 表を作り直す。

```bash
python3 mod/build_db.py
```

取得の対象は、一覧ページ、各会議体のトップページ、そこからたどれる `/j/policy/agenda/meeting/` 配下の HTML。2026-11-19 に 123 ページを取得し、未取得のサイト内ページは残っていない。`raw/mod/pages.csv` に URL・`Last-Modified`・取得日時・サイズ・SHA-256 を記録している。

## PDF の取得と本文の抽出

`documents.csv` に載っている www.mod.go.jp 上の PDF を取得し、本文をテキストにする。

```bash
python3 mod/fetch_files.py      # raw/mod/files/ に保存。台帳は raw/mod/files.csv
python3 mod/extract_text.py     # data/mod/text/ にテキストを保存。台帳は data/mod/texts.csv
python3 mod/build_db.py         # 議事要旨・議事録の冒頭から開催日時・場所・出席者を補う
```

- `fetch_files.py` は 2 秒間隔で 1 件ずつ取得し、403・429 が返ったら止まる。取得済みのものは飛ばす。PDF の本体（`raw/mod/files/`、約 350 MB）は Git に入れていない。
- 2026-11-19 に 422 件を取りに行き、421 件を保存した。1 件（再就職等監視分科会 第84回の議事要旨）はリンク切れで 404 だった。
- `extract_text.py` だけは pdfminer.six を使う。`python -m venv .venv` で仮想環境を作り、`requirements.txt` を入れて実行する。
- 画像だけの PDF からは本文が取れない。`texts.csv` の `note` に印を付けている（OCR はしていない）。
- PDF 側に文字への対応表がなく変換できなかった箇所は、`(cid:8494)` のような表記で残る（人名の一部で起きている）。

## 会議体・会議・資料・委員の表

どの表も `council_id` で会議体と結び付く。`source` は、その行を読み取ったページのサイト内パス。

`councils.csv`（行の順序は一覧ページの掲載順）：

| 列 | 内容 |
|---|---|
| `council_id` | 会議体の ID。ページのディレクトリ名（`cho-shin`、`kondankai/atsugi` など）。内閣官房のサイトにある 1 件は `cas-jieikan` |
| `section` | 一覧ページ上の区分（関係閣僚会議／審議会・有識者会議等／委員会・検討会等／アーカイブ） |
| `name` | 会議体名。リンクの文言そのまま |
| `link` | サイト内の相対パス。外部サイトの場合は URL |
| `note` | 一覧ページに添えられた注記 |
| `first_seen` | 初めて取得した日時（UTC） |

`council_profiles.csv`：各会議体の「概要」の表を、`key`（主管省庁及び庶務担当部局、根拠法令、設置年月日、所掌事務など）と `value` の縦持ちにしたもの。

`members.csv`：

| 列 | 内容 |
|---|---|
| `body` | 部会・分科会のページに載っていた名簿の場合、その名称 |
| `group` | 名簿の直前の見出し（「委員」など） |
| `as_of`、`as_of_raw` | 名簿の時点（ISO 形式と元の表記） |
| `name` | 氏名 |
| `mark`、`role` | 氏名に付いた記号（◎、○）と、凡例から読み取った役職（会長、座長代理など） |
| `title`、`note` | 職名等、備考 |

名簿は掲載時点の 1 時点分だけで、過去の委員は入っていない。

`meetings.csv`：

| 列 | 内容 |
|---|---|
| `meeting_id` | `会議体[/部会]#回次`。回次が分からない会議は `@開催日` |
| `body` | 部会・分科会の名称。同じページの中で回次を別々に数えている場合は、その見出し（「総会」「部会」「平成２４年度」など） |
| `number`、`label` | 回次と、元の表記（「第201回定例」など） |
| `date`、`date_raw` | 開催日（ISO 形式）と元の表記 |
| `time` | 開催時刻（`14:00-16:00`）。議事要旨・議事録の冒頭から |
| `agenda` | 議題。複数あるときは ` / ` で区切る |
| `place`、`attendees` | 場所と、出席者の記載そのまま。議事要旨・議事録の冒頭から。1 人 1 行にしたものは `attendance.csv` |
| `page` | その回だけを載せたページがある場合、その URL |
| `n_documents` | 結び付いた資料の件数 |
| `found_by` | 読み取りの手掛かり。`table`（開催実績の表の行）、`heading`（「第N回…」の見出し）、`link`（リンクの文言）、`page`（その回だけのページ）、`pdf`（議事要旨・議事録の本文） |

ページに書かれた値を優先し、PDF の本文は空いている項目を補うのに使う。両者の開催日や回次が食い違う場合は、`build_db.py` の実行時に警告を出す。

`attendance.csv`（各回の出席者、1 人 1 行）：

| 列 | 内容 |
|---|---|
| `group` | 資料に書かれた区分（委員、分科会委員、防衛省、防衛省側、再就職等監察官など） |
| `seq` | その回の中での記載順 |
| `name_raw` | 記載そのまま（「太田会長」「青木 節子(慶應義塾大学大学院教授)」「林服務管理官」） |
| `surname`、`role` | 姓と会議体での役職。「太田会長」→ 太田／会長。省側の出席者は職名との境目が決められないので空 |
| `roster_match` | 現在の委員名簿（`members.csv`）と照らした氏名。氏名が一致するか、同じ姓の委員が 1 人だけいる場合に入る。名簿は現時点のものなので、過去の回では同姓の別人の可能性があり、手掛かりにとどまる |
| `source` | 読み取った資料の URL |

`documents.csv`：

| 列 | 内容 |
|---|---|
| `meeting_id` | 結び付く会議。報告書や規程など、特定の回のものでなければ空 |
| `section` | 表の列見出し、または直前の見出し |
| `title` | リンクの文言 |
| `doc_type` | 文言から機械的に付けた種別（議事録、議事要旨、議事次第、資料、報告書、規程、開催案内など） |
| `url`、`host`、`format` | リンク先。`host` は `www.mod.go.jp` か `warp.da.ndl.go.jp` がほとんど |
| `text`、`pages`、`chars` | 本文を抽出済みの PDF について、テキストファイルのパス、ページ数、文字数。`chars` が 0 に近いものは画像の PDF |

会議に結び付かないサイト内ページ・外部サイトへのリンクは、案内とみなして載せていない。

### 読み取りの限界

- 933 件のうち、回次と開催日の両方が分かるのは 451 件。回次だけが 266 件、開催日だけが 216 件ある。一覧に片方しか書かれておらず、もう片方が書かれた資料が WARP にしかない会議が多い。
- 回次だけの行と開催日だけの行が同じ会議を指していても、資料から開催日が分からない限り突き合わせていない。防衛調達適正化会議（`cho-teki`）、防衛施設中央審議会（`shi-chu`）などは実際より多く数えている。
- 同じ回次で開催日が違う行は、まとめずに別の会議として残している（`meeting_id` の末尾に `@開催日` が付く）。回次を振り直している会議体（防衛省改革検討委員会 `kaikaku`）のほか、掲載側の誤記とみられるもの（`kyumei` の第６回が 2 行）がある。`build_db.py` の実行時に警告として表示される。
- 出席者は、防衛省サイトに議事要旨・議事録の PDF が残っている回に限られる（最も古いもので令和３年４月。会議体によってはここ 1〜2 年分だけ）。議事要旨・議事録 185 件のうち、出席者を読み取れたのは 165 件。公正入札調査会議は表の体裁で文字の並びが崩れ、政策評価に関する有識者会議の逐語の議事録などは出席者の一覧がない。
- 出席者の区分や名前の区切りは、資料の書き方から機械的に決めている。省側の出席者は職名だけの記載も多い。
- `doc_type` は文言だけで決めているので、目安にとどまる。

## RSS

- `update.xml`：サイト全体の更新情報。件名は「セクション｜…を更新」。審議会ページの更新は `/j/policy/agenda/meeting/` 配下へのリンクとして載る。
- `news.xml`：お知らせ（報道資料）。分科会の開催告知などが載る。
- どちらも直近約 2.5 か月分しか保持しない。本文・概要はなく、分かるのは件名・リンク・日時だけ。

```bash
python3 mod/poll_rss.py
```

`rss_items.csv` の列：

| 列 | 内容 |
|---|---|
| `feed` | `update` または `news` |
| `pub_date` | 掲載日時（ISO 8601、JST） |
| `title`、`link`、`guid`、`category`、`description`、`content` | フィードの値そのまま。`link` はサイト内の相対パス |
| `council_related` | 審議会ページ配下へのリンク、または件名に会議体らしい語を含む場合に `1`。件名による判定は目安 |
| `first_seen` | 初めて取得した日時（UTC） |

同じページが複数回更新された場合は、掲載日時ごとに別の行になる。

## 出典と利用条件

収録しているのは、防衛省・自衛隊ウェブサイトで公開されている情報と、それを加工したものである。同サイトのコンテンツは「公共データ利用規約（第1.0版）」（PDL1.0）に準拠して利用できる。

- `raw/mod/pages/`（取得した HTML）：出典：防衛省・自衛隊ウェブサイト（各ページの URL は `raw/mod/pages.csv`）、[PDL1.0](https://www.digital.go.jp/resources/open_data/public_data_license_v1.0)（2026年11月19日に利用）
- `data/mod/text/`（PDF の本文）：防衛省・自衛隊ウェブサイトの PDF（各ファイルの URL は `data/mod/texts.csv`）から、本文を機械的に抽出して作成
- `data/mod/` の各表：防衛省・自衛隊ウェブサイト（各行の `source`・`url` 列に元のページ・資料）を加工して作成

抽出と加工は本リポジトリの作成者が行ったもので、防衛省が作成した情報そのものではない。機械的な読み取りによる誤りを含みうるので、引用や分析に使う際は元の資料を確認すること。
